# EVAL — качество ETA и причинного эффекта

В этом отчёте приведены **фактические результаты**, полученные локально на отложенном периоде. Машинный отчёт с полными метриками ETA создаётся командой `make eval QUERIES=… TRUTH=… PRED=…` в `eval/report.md`. Ниже перенесены опубликованные результаты этой команды; значения не пересчитывались по отсутствующим здесь исходным CSV.

## 1. ETA: CatBoost против обязательного baseline

**Постановка.** Запрос в момент отправления и при въезде на ребро; целевая величина `remaining_s = arrive_ts - at_ts`. Baseline: кратчайшая длина от **начала текущего ребра**, делённая на фиксированную скорость (20 км/ч для гружёной, 30 км/ч для пустой машины), `p90 = 1.25·p50`. CatBoost обучает два квантиля логарифмической поправки к baseline; онлайн-прогноз использует граф, доступную телеметрию и погоду не позже `at_ts`, а не будущие события.

**Отложенная выборка:** **109 412 запросов из 5 764 поездок**. Метрики рассчитаны на идентичных запросах для обеих моделей. В опубликованном отчёте **0** отсутствующих, нечисловых или отрицательных предсказаний; при подобных случаях оценщик должен подставлять baseline, сохраняя запрос в выборке. Внутренние fallback, уже записанные в `PRED.csv`, из одних предсказаний определить нельзя — нужен лог предсказателя. Полная независимость holdout после нескольких просмотров не гарантирована; см. раздел 3.

### Основные выводы и проблемные случаи

1. **Основная масса коротких прогнозов работает хорошо:** для остатка менее 3 минут MAE CatBoost 3.784 с, coverage p90 89.68%. Для остатка 3–10 минут MAE 17.522 с, coverage 85.53% — калибровка заметно хуже.
2. **Длинные задержки — главная проблема:** при фактическом остатке более 10 минут MAE CatBoost составляет **783.022 с**, pinball p90 — **663.411 с**, coverage p90 — **12.61%**. Здесь ML лучше baseline по ошибке, но **не обеспечивает надёжный верхний квантиль**. Этот срез небольшой (920 запросов), сильно зависит от редких событий и требует отдельной проверки хвоста. Сам по себе выигрыш над baseline не доказывает практической пригодности p90 для такого режима.
3. **Новые водители:** MAE 27.860 с против 12.072 с у остальных; coverage 96.67% против 85.25%. Эти группы **определены по первому появлению в публичной истории поездок**, а не по внутреннему признаку «новый водитель» генератора. Поэтому различие нельзя полностью приписывать cold start без дополнительных проверок.
4. **Дождь:** MAE 17.446 с против 9.499 с в сухую погоду. Влияние дождя смешано с составом маршрутов и машин; прямую причинную интерпретацию из среза делать нельзя.
5. **Поломки:** публичная `edge_events.csv` не содержит причины задержки. Срез `≥600 с на ребре` — лишь прокси подозрения на длительную остановку, **не истинная метка поломки**. Подтверждённый breakdown slice на этих данных недоступен.

### Корректность сравнения и fallback

`src/eval_contract.py` подставляет baseline для отсутствующих либо некорректных строк `PRED`, не исключая запросы из оценки. По полученному полному отчёту таких строк — **0**. Это не позволяет определить внутренние fallback без журнала `make predict` (`*.fallbacks.json`). Разделение по фактическому остатку времени использует ground truth **только для оценки**, не при инференсе. Запросы одной поездки статистически зависимы: показатель по 109 412 запросам **не эквивалентен** оценке по 109 412 независимым объектам; отдельная оценка с одинаковым весом 5 764 поездок этим отчётом не подтверждена.

## 2. Causal ATT: пять разных seed

**Estimand:** `ATT=E[Y(1)−Y(0)|accepted=1]`, отрицательное значение — экономия времени. Метод `make effect`: 2-fold cross-fitted AIPW; propensity clipping `[0.05,0.95]`; 95%-CI — дневной cluster bootstrap с фиксированными nuisance-моделями. Приватная `truth/effect.json` **не используется** при оценке.

В ранних версиях симулятора ATT нельзя было надёжно оценить относительно приватной «истины»: потенциальный исход реконструировался после наблюдения или использовалась snapshot-аппроксимация. Первый полный эксперимент 5×21 день дал **MAE AIPW 130.095 с, coverage 0/5**, второй — **152.643 с, coverage 0/5**. Эти результаты относятся к *отвергнутым версиям генератора* и приведены для прослеживаемости.

### Финальная структурная модель: подтверждённый **короткий** прогон

Сначала создаются `Y(0)` и `Y(1)` по предрешенческим ковариатам, далее выбирается принятие и наблюдается соответствующий исход. В пяти сценариях использовано **4 дня, 80 узлов, уменьшенное число итераций AIPW**:

| Seed | Selection strength | True ATT (с) | AIPW ATT (с) | Абс. ошибка (с) | Истина внутри 95% CI |
|---|---:|---:|---:|---:|---|
| 42 | 0.0 | −227.980 | −231.118 | 3.138 | Да |
| 43 | 0.5 | −267.117 | −268.565 | 1.448 | Да |
| 44 | 1.0 | −269.815 | −268.556 | 1.259 | Да |
| 45 | 1.5 | −276.633 | −273.638 | 2.995 | Да |
| 46 | 2.0 | −272.512 | −265.731 | 6.781 | Да |

Сводка: **MAE AIPW 3.124 с**, **MAE naive 80.082 с**, **попадание 5/5**. Прогнозируемый `est_gain_s` смещён относительно истинного выигрыша у принявших в среднем на **+113.187 с** (согласованный знак: `est_gain_s + individual_effect_s`). Это наблюдаемый результат *короткой* проверенной конфигурации, **не доказательство 95% покрытия вообще**.

**Полный прогон пяти независимых сценариев по 21 дню после финальной правки остаётся непроверенным в этом документе.** Команда:

```bash
make effect-validate WORK=build/effect_validation_final DAYS=21 NODES=200
```

Отчёты: `build/effect_validation_final/effect_validation.csv` и `.json`. Только после его завершения следует добавлять в этот документ метрики полного сценария.

### Проверка нулевого эффекта

Генератор поддерживает `CAUSAL_EFFECT_SCALE=0`, для чего `Y(1)=Y(0)` и приватный ATT равен нулю. Есть тест этой тождественности и **отдельный** синтетический тест, где 95%-CI AIPW накрывает ноль. Полноценный end-to-end тест покрытия CI при нулевом эффекте *в одном наборе от событийного генератора* отдельно не подтверждён.

### Ограничения интерпретации

- Текущий `outcome_s` — структурный causal-исход, **не буквальное фактическое время до начала обслуживания в событийной симуляции**. Это несоответствие физической части исходного ТЗ требуется признавать.
- Модель `accepted` в финальном эксперименте зависит от наблюдаемых ковариат; скрытое смешение причин, интерференция машин и очередей остаются проблемами для реального карьера.
- Bootstrap переиспользует обученные nuisance-модели, что способно сузить доверительный интервал.
- Эксперименты разных seed одновременно меняют граф/условия; они проверяют устойчивость к смене сценария, а не изолируют только selection bias.
- Несколько запросов одного рейса связаны. Кластеры по рейсу/смене и блочный bootstrap — отдельные элементы эксплуатационной проверки.

## 3. Воспроизводимость и границы окончательных выводов

Внешний временной holdout ETA уже просматривался неоднократно. Нет независимого финального повторного теста на свежем закрытом наборе. `truth/` отделена от `DATA_DIR`, но приватная истина построена в упрощённой структурной модели, а не полноценным replay двух миров. Выводы из этой синтетики **не переносятся автоматически** на реальную карьерную площадку.
