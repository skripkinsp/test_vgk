# Quarry haulage: ETA и эффект рекомендаций

Решение тестового задания **Senior ML Engineer — прогнозы и качество решений**: синтетический карьер, прогноз оставшегося времени движения (`p50`, `p90`) и наблюдательная оценка эффекта рекомендаций (ATT). Реализация на Python; синтетические данные генерируются без сети. По умолчанию часовой пояс площадки — `Asia/Yekaterinburg`, в CSV время записано в UTC epoch seconds.

> **Подтверждённые результаты ETA:** отложенный период — **109 412 запросов, 5 764 поездки**; MAE p50 **81.534 с** (Дейкстра) против **15.248 с** (CatBoost); pinball p90 **55.343 с** против **8.333 с**; coverage p90 CatBoost **87.55%** (ниже номинальных 90%), на фактическом остатке >10 минут — **12.61%**. Полные срезы и ограничения — в [EVAL.md](EVAL.md).

> **Статус и границы:** реализованы генератор, ETA baseline и CatBoost, генерация запросов, оценка, benchmark, AIPW ATT, приватная структурная causal truth и тесты. Полный 21-дневный прогон **последней** causal-версии на пяти seed на момент фиксации этой версии документа не подтверждён; доступна проверка пяти *4-дневных* сценариев. Точное выполнение SLA на разнообразном потоке и разрез подтверждённых поломок тоже не доказаны. Подробности — в [EVAL.md](EVAL.md).

## Требования и установка

- Python **3.10+** (проверять в своём окружении); GNU Make необязателен, его команды эквивалентны `python -m`.
- Python-пакеты: `numpy`, `pandas`, `catboost` (GPU не нужен).
- Запуск из **корня проекта**, где находятся `Makefile`, `src/` и `data/`.

```bash
python -m pip install numpy pandas catboost
python -m unittest discover -s tests -v
```

Для PowerShell/VS Code без `make` используйте команды `python -m src.…` из примеров ниже.

## Быстрый путь: уже есть `data/`

Первый набор симулируется с 1 сентября 2025 года в 03:00 UTC и охватывает 21 день; последние три дня зарезервированы для временного теста. Убедитесь, что ваши CSV действительно относятся к этому диапазону, прежде чем использовать даты примера.

```bash
# 1. Обучение на поездках, ЗАВЕРШЁННЫХ до 19.09.2025 03:00 UTC
make train UNTIL=2025-09-19T03:00:00+00:00

# 2. Отложенные запросы; FROM включительно, TO исключительно
make queries FROM=2025-09-19T03:00:00+00:00 TO=2025-09-22T03:00:00+00:00 OUT=build/test

# 3. Два прогноза
make predict QUERIES=build/test/queries.jsonl OUT=build/test/catboost.csv
make baseline QUERIES=build/test/queries.jsonl OUT=build/test/baseline.csv

# 4. Оценка по интерфейсу задания
make eval QUERIES=build/test/queries.jsonl TRUTH=build/test/truth.csv PRED=build/test/catboost.csv

# 5. Диагностика отдельных поездок и benchmark
make diagnostics TEST_DIR=build/test
make bench QUERIES=build/test/queries.jsonl

# 6. Causal ATT (независимо от ETA)
make effect DATA_DIR=data
```

Тот же процесс **без GNU Make**:

```bash
python -m src.eta_model train --data data --model model --until 2025-09-19T03:00:00+00:00
python -m src.queries --data data --from 2025-09-19T03:00:00+00:00 --to 2025-09-22T03:00:00+00:00 --out build/test
python -m src.eta_model predict --data data --model model --queries build/test/queries.jsonl --out build/test/catboost.csv
python -m src.baseline --data data --queries build/test/queries.jsonl --out build/test/baseline.csv
python -m src.eval_contract --data data --queries build/test/queries.jsonl --truth build/test/truth.csv --pred build/test/catboost.csv --out eval/report.md
python -m src.bench --data data --model model --queries build/test/queries.jsonl --out build/test/bench.json
python -m src.effect --data data --out effect.json
```

### Если данных ещё нет

```bash
make data                          # DATA_DIR=data, TRUTH_DIR=truth, seed=42, 21 день
make validate
make test
```

Для нового набора: `make data DATA_DIR=another_data TRUTH_DIR=another_truth SEED=43 DAYS=21 NODES=200`. Генератор перезаписывает целевые CSV в выбранном `DATA_DIR`; не запускайте это поверх нужных данных без копии. **Для causal-экспериментов** удобнее отдельная рабочая папка:

```bash
make effect-validate WORK=build/effect_validation_final DAYS=21 NODES=200
```

Этот запуск создаёт пять самостоятельных наборов (seed 42–46, `selection_strength` 0…2) и файл `effect_validation.csv`. Повторное оценивание существующих наборов: `make effect-validate WORK=build/effect_validation_final REUSE=1`.

### Настройки Makefile

- `DATA_DIR` — входные публичные данные, по умолчанию `data`.
- `TRUTH_DIR` — приватная истина генератора, по умолчанию `truth`; **не должна читаться** моделями или оценивателем.
- `MODEL_DIR` — каталог модели, по умолчанию `model`.
- `UNTIL` — обязательный временной cutoff обучения, исключающий поездки с `arrive_ts >= UNTIL`.
- `FROM`, `TO`, `OUT` — создание запросов, `OUT` обозначает каталог.
- `QUERIES`, `TRUTH`, `PRED` — входы `make eval`, результат — `eval/report.md` (или путь `OUT`).
- `SEED`, `DAYS`, `NODES`, `SELECTION_STRENGTH`, `CAUSAL_EFFECT_SCALE` — параметры генератора; последнее значение 0 задаёт нулевой причинный эффект в структурном эксперименте.

| `src/eval_contract.py`, `src/eval.py`, `src/diagnostics.py`, `src/bench.py` | Отчёт по интерфейсу ТЗ, вспомогательная оценка, диагностика, задержка |

| `model/` | `q50.cbm`, `q90.cbm`, `meta.json` |
| `build/test/`, `eval/` | `queries.jsonl`, `truth.csv`, прогнозы, сравнения, `bench.json`, `eval/report.md` |

Граф: ~200 связанных узлов дорожной сети 30×40 с шагом 50 м и два тупиковых пункта разгрузки; три пункта погрузки; уклоны не выше 8%, покрытия `paved`, `gravel`, `dirt`. Автопарк: 30 машин трёх классов, 60 основных сменных водителей и новые водители в последние три дня. Генератор моделирует дождь и инерцию влажности, загрузку, уклон, трафик, редкие отказы, очереди и дефекты телеметрии. При генерации маршрутов используются Дейкстра и алгоритм Йена (до пяти альтернатив).

**ETA:** обязательный baseline — кратчайшее расстояние от *начала текущего ребра* / 30 км/ч пустой либо 20 км/ч гружёный; `p90=1.25·p50`. CatBoost обучает два квантиля поправки `log(remaining_s / baseline_eta_s)`, используя только текущий запрос, граф, машины, `site.json` и почасовую погоду **не позже** момента запроса. `predict` выводит CSV `query_id,p50_s,p90_s`, обеспечивает `p90 >= p50`, при ML-ошибке применяет baseline. Счётчик fallback выводится в терминал и в `*.fallbacks.json`.

**ATT:** кросс-фиттинг по дням, CatBoost propensity + контрольный outcome-регрессор, AIPW, ограничение propensity в `[0.05,0.95]`, дневной кластерный bootstrap с фиксированными nuisance-моделями. `effect.json` имеет поля `att_s,ci95,naive_s,method`. Знак отрицательный — сокращение времени.

## Критические упрощения

1. **Causal truth — отдельная структурная модель**, создающая `Y(0)` и `Y(1)` до выбора действия, затем публикующая один `outcome_s`. Она не воспроизводит фактический момент начала обслуживания из событийной очереди и не моделирует воздействие решения на других самосвалов. Это **ограничение относительно буквальной физической трактовки `outcome_s` в ТЗ**, а не полноценный digital twin.
2. Решение о принятии рекомендации в финальной структурной постановке зависит от наблюдаемых предрешенческих ковариат (`est_gain_s`, время суток, модель). Скрытый confounding в реальном карьере этим **не устранён**.
3. Пропущенное первое ребро нельзя всегда восстановить из дефектной телеметрии: `queries.py` иногда приближённо определяет его по графу. Запросы в момент входа на полностью отсутствующее в телеметрии ребро не восстановить.
4. Публичные `edge_events.csv` не содержат признака поломки. Отчёт допускает только **прокси длительной остановки**, не подтверждённые поломки.
5. Benchmark на одном повторяемом запросе оценивает прогретый кэш, исключая загрузку моделей; он не доказывает SLA для разнообразного потока и холодных пар маршрут–назначение. Проверка использования строго одного CPU-потока на целевой среде обязательна.
6. Истинный эффект в реальной среде не наблюдается, а пять независимых сценариев недостаточны для достоверного измерения покрытия номинального 95%-CI.

## Время, работа с ИИ и история holdout

- Работа велась с **ChatGPT (генерация кода, анализ форматов, тесты, помощь с документацией)**. Пользователь выбирал сетку/маршруты/физические зависимости, проверял реализацию, запускал полные эксперименты локально и оспаривал причинную корректность. Ассистент писал первичные версии модулей и диагностировал ошибки. За корректность результата и финальные решения отвечает автор сдачи.
- Затраченное время **не фиксировалось точно**; фактически работа шла **более двух календарных дней**, то есть существенно дольше заложенных 6–8 часов.
- Ошибки в сгенерированных решениях, обнаруженные и исправленные в ходе работы: (1) приватный ATT сначала считался из приближённой snapshot-разницы, затем — из остатка **после** принятия; (2) при первом исправлении оставался скрытый confounding и 0/5 покрытия; (3) `make eval` первоначально использовал `TEST_DIR`, а не требуемый интерфейс `QUERIES/TRUTH/PRED`. Были также обнаружены дубли триггеров на старте и пропуски телеметрии.
- Последний трёхдневный holdout **просматривался неоднократно** при оценке ETA и диагностике; точное число просмотров не записано. Поэтому он **не является полностью нетронутым тестом для любых новых решений**. Показатели с него описываются как полученная оценка, но не используются для обоснования последующего тюнинга. Новая независимая оценка требует нового seed/периода, зафиксированного заранее.
